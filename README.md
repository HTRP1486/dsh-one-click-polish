# 一键润色 / 扩写 / 自动驾驶

给 DeepSeek Harness（dsh）桌面端的输入框加一组动作：**润色**、**扩写**、**自动驾驶**。所有模型调用都用**你当前会话正在用的那个模型**，结果直接写回输入框。

- 润色：按三档深度重写草稿
- 扩写：把一句话扩写成能直接开工的需求说明
- 自动驾驶：让 AI 读对话、写下一步提示词、发给助手，一轮接一轮推进到你设定的目标

---

## 安装

```bash
dsh plugin --profile <你的 profile 名> install github:HTRP1486/dsh-one-click-polish
```

或者用 `plugin_manager` 的 `install_bundle`，把仓库目录或 `.tgz` 包作为 target。

装好后重启 dsh（或让 HMR 接管），输入框左下角出现 `润色 | 深度 | 扩写 | 自动`，设置里多出「润色 / 扩写」一页。

## 用法

### 润色

打字 → 点 `润色` → 草稿被重写并写回。

档位胶囊点一下循环 `轻度 → 标准 → 深度`（默认深度，记在浏览器本地）。它决定**动手前查多少资料**：

| 档位 | 动手前 | 改写力度 |
| --- | --- | --- |
| 轻度 | 什么都不查 | 只改错别字、标点、语法 |
| 标准 | AI 翻项目目录和 dsh 配置目录，找相关文件 | 改措辞和句式、去冗余 |
| 深度 | 标准 + 联网检索（必应 / 百度 / GitHub） | 重组结构、拆长句、换精准用词 |

检索不是关键词匹配：Host 把 `list_dir` / `read_file` / `search_files` / `search_content` / `web_search` 交给模型，由它自己决定查什么、要不要再追一轮（最多 6 轮、90 秒、6000 字资料）。**只读**，越出项目目录与 dsh 配置目录的路径会被拒绝。

### 扩写

输入一句粗需求，例如 `帮我写一个登录功能`，点 `扩写`。

输出**没有固定模板**：8 个字的小需求给八百字短说明，系统级需求才展开成带角色权限、边界、验收的长文。它会读最近 16 条对话，所以知道你在做什么产品、哪些决策已经定了。

### 自动驾驶

点 `自动` 弹出面板：

```
自动驾驶
○ 循环几次结束      [ 5 ]
☑ 限制运行时间      [ 0 ] 小时  [ 30 ] 分钟
○ 直到达成目标结束

目标（可选）：写清楚要达成什么，达成后自动停；不填就只看轮数
[                                    ]

[ 启动 ]
```

点启动 → 确认弹窗 → 才真正开始。运行中再点 `自动`：

```
运行中 3/5 · 已跑 12 分钟
上下文：8 条消息 / 1300 字
查看驱动 AI 读到的上下文

[ 中断 ]  [ 结束循环 ]
```

- **中断**：掐掉当前这一轮，循环继续，它会重新判断再发一条
- **结束循环**：整个关掉
- 轮数用尽 / 时间到 / 目标达成 / 出错 / 你点停 —— 五种情况都会立刻停机

停止条件可以叠加：`循环 5 次 + 填个目标` = 最多 5 轮，做完了提前收工。

**它读到的对话你能看见**：面板里的「查看驱动 AI 读到的上下文」会显示这一轮实际传给驱动 AI 的对话全文。

## 换窗口 / 重启 会怎样

| 场景 | 结果 |
| --- | --- |
| 切会话、切标签、最小化 | 继续跑（在 Host 进程里） |
| 切走再回来 | 继续跑，按钮上轮数跟着涨 |
| 重启 dsh | 不自动跑，面板里给「从中断处继续」按钮，点了才续 |

每轮都会把进度写进 profile 目录的 `.one-click-polish-autopilot.json`，重启后据此提供恢复入口。正常结束会自动清掉。

## 设置

**设置 → 润色 / 扩写**：

| 项 | 说明 |
| --- | --- |
| 模型来源 | `跟随当前对话`（默认）用输入框里选中的模型；`固定模型` 始终用指定那个 |
| 模型 | 选 `固定模型` 后出现，带搜索的下拉框，按供应商分组 |
| 思考程度 | 照 dsh 的 `Default / Low / High / Max` 做，**选项按该模型实际支持的档位生成**，不支持就整栏隐藏；换模型时旧档位自动回落 |

改动先留在页面上，点 `保存` 才写入 profile，`撤销修改` 回到上次保存的状态。

## 配置

在 profile 的 `cordis.patch.yml` 里覆盖本行 `config`：

```yaml
- id: one-click-polish
  config:
    modelSource: follow      # follow | fixed
    provider: ''             # modelSource 为 fixed 时必填
    model: ''
    reasoningEffort: ''      # '' = 默认；否则必须是该模型支持的档位
    defaultStrength: strong  # light | standard | strong
    maxInputChars: 12000     # 单次输入字符上限
    timeoutMs: 120000        # 单次请求超时
    instruction: ''          # 追加给模型的额外要求
```

## 原理

- **模型解析**在 Host 侧：会话日志里最新的 `model/selection` → 最近一次 `request/header` → profile 默认模型。所以模型选择器切到哪个就用哪个，切了还没发消息也认得。
- **润色 / 扩写**是手工构造的 `llm.stream()`：不写会话日志、不开 Turn、不动对话历史，只借一次模型能力。
- **长任务用 202 + 轮询**：桌面 webview 会掐断长时间静默的请求，所以 `POST …/polish` 立刻返回 202，浏览器每 700ms 轮询 `GET …/progress` 取结果。
- **自动驾驶**用 `agent.followup()` 往会话里追加用户消息并唤醒，用 `await agent.whenIdle()` 等这一轮跑完。每轮按 session id 重新取 agent，所以切换会话销毁重建 agent 也不影响。

## HTTP 接口

都在 `/plugins/dsh-one-click-polish` 下：

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | `/polish` | 提交润色/扩写任务，返回 202 + requestId |
| GET | `/progress?id=` | 轮询任务状态与结果 |
| GET/POST | `/settings` | 读/写设置与模型目录 |
| GET | `/efforts?provider=&model=` | 某模型支持的思考档位 |
| GET/POST | `/autopilot` | 读/写自动驾驶状态，`?resumable=1` 列可恢复的运行 |
| GET | `/status` | 当前会话解析到的模型 |
| GET | `/diag` | 排查用：会话、目录、上下文快照 |
